# 打分小系统（扫码打分）

终端公司 TeleAgent 竞赛案例评审的**线上打分小系统**：评委扫二维码进入打分页，为每个案例填写总分（0–100，必填）和 5 个维度分（选填）；后台自动做**去最高最低分取平均 + 排序**，供工作组查看与导出。初评、复审各一套打分页和二维码。

## 功能

- 两个轮次：初评（默认 60 个案例）、复审（默认 30 个案例），分别打分、分别统计。
- 打分结构：每案例 = 5 个维度分（立足实际场景≤20 / 体现赋能价值≤20 / 成效真实可验证≤20 / 坚持原创合规≤10 / 具备推广价值≤30，选填）＋ **总分 0–100（必填）**。
- 计分规则：每案例取全部评委的**总分**，**去掉一个最高分和一个最低分**后取算术平均（保留 2 位小数；专家数 ≤2 时直接取平均），按平均分排序，同分并列。
- 评委同名重复提交覆盖上次；未填总分的案例自动跳过。
- 管理端（需密码）查看结果、导出 CSV；每轮一键生成二维码。

## 公网部署（GitHub Pages 前端 + 免费云后端）

> 一键照做看《部署指南.md》：前端打分页放 GitHub Pages、后端存数据放 Railway（免费带数据卷），并给出二维码与访问链接、验证清单。

系统是无状态 Flask 应用，可部署到任一台有公网入口的主机。三种常用方式：

### 方式一：云服务器 / VPS（推荐，正式使用）

1. 把 `打分小系统` 目录上传到服务器，装 Python3 + 依赖。
2. 改 `config.json`：`public_base_url` 填你的公网域名/地址；`admin_pass`、`judge_pass` 改掉。
3. 用生产 WSGI 启动（Gunicorn 示例）：
   ```bash
   pip install gunicorn
   gunicorn -w 2 -b 0.0.0.0:8000 app:app
   ```
4. Nginx 反代到 8000，配 HTTPS 域名；或直接对公网开放 8000 端口（注意安全组）。
5. 打开 http://你的域名/，进入各轮次 → 查看/下载对应二维码，打印后供评委扫码。

### 方式二：内网穿透（无服务器时快速公网，临时用）

本机先按"本地运行"启动，再用穿透工具暴露 8000：
- ngrok：`ngrok http 8000`，得到公网 https 地址，把该地址填到 `config.json` 的 `public_base_url`，重新打开 /qr 生成二维码。
- 或 cpolar / frp 同理。

### 方式三：云函数 / 轻量 PaaS（需要改少量代码）

本项目为标准 Flask，可直接放到 Fly.io / Render / Railway / 国内云 PaaS（打包依赖 + 挂载持久化 `data/data.json`，因无状态容器需把数据存到卷/对象存储）。

> 说明：本项目默认把数据存在本地 `data/data.json`（最简单、符合"本地留痕"）。部署到无状态 PaaS 时需把该文件放到持久化卷，否则重启丢数据。若你只需要短时收集、结束后留档导出，单机部署即可。

## 使用流程

1. 配置好案例与口令 → 启动 → 复制各轮次二维码发给评委。
2. 评委扫码 → 填姓名（必答）→ 逐案例填总分（+选填 5 维度分）→ 提交。可重复提交，同名覆盖。
3. 结束后，工作组进 /admin（密码）→ 查看去极值平均分与排名 → 导出 CSV 留档/汇总。
4. 导出后务必**备份 data/data.json**。

## 安全与留痕

- 公网部署务必设置 `judge_pass`（评委口令）并修改 `admin_pass`。
- 问卷/评分页建议仅在评审周期开放，结束后可停止服务或改口令。
- 成绩本地留痕，符合"全程留痕、双人复核"要求；导出后双人复核再使用。
